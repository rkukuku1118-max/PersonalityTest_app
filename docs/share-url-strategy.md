# 診断結果をURLだけで共有するための戦略

## 目的

診断結果を自前サーバーやデータベースへ保存せず、共有URLを開くだけで受信者が結果を閲覧できるようにする。

共有データはURLのフラグメント（`#`以降）へ格納する。

```text
https://example.com/#share=エンコードされた結果データ
```

フラグメントは通常のページ取得時のHTTPリクエストに含まれないため、結果データをアプリのサーバーやCDNへ送信せずに画面を再構築できる。

共有先のサービスにはURL全体が渡り、リンクを知っている人は結果を閲覧できる。親しい人との個人チャットなどでの利用を勧め、最終的な共有先はユーザー自身に判断してもらう。

## 基本方針

- `localStorage`全体を共有しない
- 質問ごとの回答は共有しない
- 診断から算出したスコアだけを共有する
- 共有結果にも通常と同じ結果画面・表示コンポーネントを使用する
- 受信した結果を自動的に`localStorage`へ保存しない
- 保存したい場合だけ、共有結果に専用の保存ボタンを表示する
- 共有画面を開いただけでは外部AIへデータを送信しない
- 個人ごとのSNSプレビュー画像は作らず、共通OGPを使用する

## URLへ含めるデータ

### 含める情報

- URLデータ形式のバージョン
- 60問版または100問版の識別子
- 採点・評価基準のバージョン
- 因子スコア
- 下位尺度スコア

### 含めない情報

- 質問ごとの回答
- 診断履歴ID
- 氏名やニックネーム
- ローカル保存日時
- AIレポート全文
- その他の`localStorage`情報

### データ例

スコアは`3.19`ではなく`319`のような整数にして、URLを短く保つ。

新しく作る共有URLでは、因子IDやフィールド名の繰り返しを避けるため、データ形式`v: 2`の固定順配列を使用する。

```json
{
  "v": 2,
  "t": 100,
  "s": 1,
  "x": [319, 343, 350, 294, 344, 341, 390, 310, 320, 330, 316, 340, 350, 342, 340, 345, 355, 348, 290, 300, 295, 291, 350, 340, 345, 341, 330, 350, 345, 339, 390, 390]
}
```

- `t`: テスト種別。`60`または`100`
- `s`: 採点・評価基準のコード。`1`は`hexaco-ja-1`
- `x`: テスト定義に記載された順の因子スコア、その後に同じく定義順の下位尺度スコア

日本語ラベルや因子IDはURLへ格納せず、受信側でデータ形式、テスト種別、固定順から復元する。

## エンコード方式

MVPでは次の方式を採用する。

```text
共有対象データを作成
→ JSONへ変換
→ UTF-8へ変換
→ Base64URLでエンコード
→ #share=の後ろへ追加
```

最初から圧縮ライブラリは導入しない。実際の共有URL長を計測し、必要になった場合だけ圧縮を追加する。

## 画面構成

アプリ起動時に`location.hash`を確認する。

```text
#share=がない
  → 通常どおりアプリを起動

#share=がある
  → データを検証・復元
  → 通常と同じ結果画面へ渡す
```

共有専用の結果画面は新設しない。通常の診断直後、履歴からの表示、共有URLからの表示で、同じ結果画面コンポーネントを使用する。

```text
診断直後の結果 ─┐
履歴の結果 ─────┼→ 共通の結果画面
共有URLの結果 ──┘
```

因子スコア、AIレポート、下位尺度などの表示順・デザイン・評価ロジックは共通化する。共有結果だけ別のデザインへ分岐させない。

違いは「データの出所」と「実行可能な操作」だけに限定する。共有URLから開いた場合は、通常の結果見出し付近に「共有リンクから表示中」という短い状態表示を加える。専用ページのような強い見た目の差は付けない。

結果画面へ渡す状態は、複数の真偽値ではなく次のような出所で管理する。

```text
current  診断直後の結果
history  保存済み履歴の結果
shared   共有URLから復元した結果
```

各状態の操作は次のようにする。

| 出所 | 結果表示 | 回答の見直し | 自動保存 | 専用の保存ボタン |
|---|---|---|---|---|
| `current` | 共通画面 | 可能 | 現在の仕様どおり | 不要 |
| `history` | 共通画面 | 不可 | 保存済み | 不要 |
| `shared` | 共通画面 | 不可 | 行わない | 表示する |

共有結果には質問回答が含まれないため、「回答を見直す」は表示しない。代わりに「自分も診断する」を表示する。

## 共有結果の保存方針

共有URLを開いた時点では、復元した結果をメモリ上だけに保持する。画面表示、AIレポート生成、ページ内操作を理由に、履歴へ自動追加してはならない。

`shared`状態かつ未保存の場合だけ、結果画面に次のボタンを表示する。

```text
［この結果を端末に保存］
```

保存ボタンの近くには、次の説明を表示する。

> この共有結果はまだこの端末に保存されていません。保存すると診断履歴から確認できます。

ボタンを押した場合だけ、共有結果を新しい履歴として`localStorage`へ保存する。
この際、誰の共有結果がわからなくならないため、ラベルを入力する

保存対象は以下とする。

- テスト種別
- 因子スコア
- 共有ペイロードに含まれている下位尺度スコア
- 採点基準のバージョン
- 保存日時
- 共有結果であることを示す`source: "shared"`
- 保存前の同じ画面で生成したAIレポートがあれば、その生成結果
- 共有元を示すユーザーが登録したラベル

質問回答、共有者の履歴ID、共有者の保存日時は保存しない。

保存に成功したら、保存ボタンを「この端末に保存済み」という状態表示へ置き換える。失敗した場合は未保存のままにし、原因を画面上へ通知する。

同じ共有結果を繰り返し保存しないよう、正規化した共有ペイロードからブラウザ内で識別値を作る。同じ識別値が履歴にある場合は新規追加せず、保存済みとして扱う。識別値の作成や照合も端末内だけで行う。

共有結果からAIレポートを生成する場合も、生成操作だけで履歴を作成しない。未保存中の生成結果はメモリ上に保持し、その後ユーザーが保存ボタンを押した場合に共有結果とまとめて保存する。

## バージョン管理

共有済みURLを将来も再現できるように、2種類のバージョンを持たせる。

- `v`: URLデータ形式のバージョン
- `scoring`: 採点・評価基準のバージョン

採点基準を変更しても古い共有URLを壊さないよう、公開後は旧バージョンのデコード処理を残す。

評価ラベルはURLへ直接格納せず、原則として「スコア＋採点基準バージョン」から復元する。これにより、どの基準で評価された結果かを追跡できるようにする。

現在、新規共有URLは固定順配列を使用する`v: 2`で生成する。初期のID付きオブジェクト形式である`v: 1`は、すでに共有されたURLを引き続き表示できるようデコード処理を残す。

## 入力検証

共有URLは第三者が自由に書き換えられるため、デコードした内容を信用しない。

受信時に以下を検証する。

- 対応しているデータ形式か
- 対応している採点基準か
- テスト種別が60問版または100問版か
- 許可された因子IDだけが含まれているか
- スコアが100から500の範囲内か
- 因子がそろっているか
- URLとペイロードが想定サイズ以内か
- HTMLやスクリプトとして解釈される文字列がないか

不正な場合は部分的に結果を表示せず、エラー画面へ切り替える。

```text
この共有リンクは無効か、現在のバージョンでは表示できません。
```

サーバーを使用しない構成では、リンクが本物の診断結果であることを証明できない。「検証済み」「公式な結果」といった表示は行わない。

## 共有操作

共有の主操作は、SNSや特定アプリを直接開くボタンではなく「共有リンクをコピー」とする。

```text
［共有リンクをコピー］
```

OS標準の共有メニューは公開SNSも共有先として表示するため、導入する場合も副操作として扱う。共有先をアプリ側で制限できないことを前提とし、主操作にはしない。

共有は次の流れとする。

1. ユーザーが「共有リンクを作る」を押す
2. URLに含まれる内容と共有時の注意を確認する
3. 「共有リンクをコピー」を押す
4. 親しい人との個人チャットなどに貼り付ける

確認画面には次の説明を表示する。

> このリンクには、あなたの性格因子と下位尺度のスコアが含まれます。質問への回答や氏名は含まれません。
>
> 親しい人との個人チャットなどでの共有におすすめです。
>
> リンクを知っている人は結果を閲覧できるため、共有先をご確認のうえ、ご自身の判断でご利用ください。


リンクをコピーした後は、次の案内を表示する。

> 共有リンクをコピーしました。共有先をご確認のうえご利用ください。


## プライバシーと安全性

フラグメント方式は、自前サーバーへ結果を保存しないことを実現する。一方で、次の制約がある。

- 共有先のサービスにはURL全体が渡る
- URLを転送された第三者も閲覧できる
- 一度共有したリンクを後から無効化できない
- 有効期限を設定できない
- ページ内のJavaScriptはフラグメントを読み取れる
- URLを書き換えた結果との区別や真正性の証明はできない

結果画面では、共有フラグメントを読み取る必要のない広告、外部解析タグ、第三者スクリプトへ共有データを渡さない方針とする。

共有結果でも通常と同じAIレポートUIを使用できる。ただし閲覧しただけでは送信せず、受信者が明示的に生成ボタンを押した場合だけ外部AIへスコアを送信する。
